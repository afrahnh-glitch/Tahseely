# رصيد التميز التحصيلي

نظام ويب لرصد مشاركات مسابقة التحصيلي الأسبوعية (فيزياء · كيمياء · أحياء) لـ 280 طالبة في 9 فصول.
HTML وCSS وJavaScript فقط، مع Firebase Authentication وCloud Firestore، ويُنشر على GitHub Pages.

**الحالة الآن:** يعمل في «الوضع التجريبي» ببيانات وهمية حتى تُضاف إعدادات Firebase في `js/firebase-config.js`.

---

## 1. محتوى المجلد

| الملف | دوره |
| --- | --- |
| `index.html` | لوحة المعلمات والمديرة |
| `display.html` | شاشة العرض العامة (بلا دخول، قراءة فقط) |
| `js/firebase-config.js` | **المكان الوحيد الذي تضعين فيه إعدادات مشروعكِ** |
| `js/app.js` | الواجهة |
| `js/scoring.js` | قاعدة احتساب النقاط |
| `js/store-firestore.js` | الحفظ في Firestore (عملية واحدة لكل رصد) |
| `js/store-demo.js` | البيانات الوهمية للوضع التجريبي (أو افتحي الرابط مع `?demo=1`) |
| `js/pdf-names.js` + `js/vendor/` | قراءة أسماء كشف نور من PDF (مكتبة pdf.js محلية) |
| `firestore.rules` | قواعد الأمان (تُلصق في Firebase Console) |
| `firestore.indexes.json` | الفهرسان المطلوبان (مرجع للخطوة 2-5) |
| `tests/` | الاختبارات (لا حاجة لرفعها مع الموقع) |

## 2. إعداد Firebase من Safari على الآيباد

افتحي **console.firebase.google.com** وسجّلي الدخول بحساب Google. يُفضّل وضع الآيباد أفقيًا.

### 2-1 إنشاء المشروع
1. اضغطي **Create a project** (أو **Add project**).
2. اكتبي اسمًا للمشروع، مثل: `rased-tamayuz`.
3. يمكنكِ إيقاف Google Analytics، فالنظام لا يحتاجه.
4. انتظري حتى يكتمل الإنشاء، ثم **Continue**.
5. ابقي على الخطة المجانية **Spark**. النظام لا يحتاج خطة مدفوعة.

### 2-2 تفعيل تسجيل الدخول
1. من القائمة: **Build ← Authentication ← Get started**.
2. تبويب **Sign-in method** ← **Email/Password** ← فعّلي الخيار الأول فقط ← **Save**.
3. تبويب **Users** ← **Add user** ← بريدكِ وكلمة مرور قوية ← **Add user**.
4. في صف حسابكِ انسخي قيمة **User UID** واحتفظي بها (ستحتاجينها في 2-6).

> كلمة المرور تبقى عندكِ فقط، ولا ترسليها لأحد.

### 2-3 إنشاء قاعدة البيانات
1. **Build ← Firestore Database ← Create database**.
2. اختاري موقعًا قريبًا من القائمة، مثل الدمام `me-central2` إن ظهر. **الموقع لا يتغير بعد الإنشاء.**
3. اختاري **Start in production mode**، فتكون القاعدة مغلقة تمامًا حتى نضع القواعد.

### 2-4 قواعد الأمان
1. داخل Firestore Database افتحي تبويب **Rules**.
2. احذفي كل ما فيه، والصقي محتوى الملف `firestore.rules` كاملًا.
3. اضغطي **Publish**.

### 2-5 الفهرسان المطلوبان
تبويب **Indexes** ← **Composite** ← **Create index**، وأنشئي فهرسين:

| Collection ID | الحقل الأول | الحقل الثاني | Query scope |
| --- | --- | --- | --- |
| `students` | `active` · Ascending | `totalPoints` · Descending | Collection |
| `students` | `classId` · Ascending | `totalPoints` · Descending | Collection |

يحتاج كل فهرس بضع دقائق حتى تصبح حالته **Enabled**.

### 2-6 جعل حسابكِ مديرة للنظام (مرة واحدة)
1. Firestore Database ← تبويب **Data** ← **Start collection**.
2. Collection ID: `users` ← **Next**.
3. Document ID: الصقي **User UID** من الخطوة 2-2.
4. أضيفي أربعة حقول:

| Field | Type | Value |
| --- | --- | --- |
| `name` | string | اسمكِ |
| `email` | string | بريدكِ |
| `role` | string | `admin` |
| `active` | boolean | `true` |

5. **Save**.

هذه هي الطريقة الوحيدة لإنشاء أول مديرة. لا توجد في الواجهة أي طريقة لترقية حساب إلى مديرة إلا من مديرة موجودة.

### 2-7 استخراج إعدادات تطبيق الويب
1. أعلى القائمة الجانبية: رمز الترس ⚙️ ← **Project settings**.
2. تبويب **General** ← انزلي إلى **Your apps** ← اضغطي رمز الويب **`</>`**.
3. App nickname: `rased-web`. **لا** تفعّلي Firebase Hosting ← **Register app**.
4. ستظهر كتلة تبدأ بـ `const firebaseConfig = {`. انسخي ما بين القوسين `{ … }` كاملًا.
5. إن أغلقتِها: Project settings ← General ← Your apps ← **SDK setup and configuration** ← **Config**.

### 2-8 لصق الإعدادات في المشروع
افتحي `js/firebase-config.js` واستبدلي السطر:

```js
export const firebaseConfig = null;
```

بما نسختِه، بهذا الشكل:

```js
export const firebaseConfig = {
  apiKey: "…",
  authDomain: "…",
  projectId: "…",
  storageBucket: "…",
  messagingSenderId: "…",
  appId: "…"
};
```

هذه القيم **ليست سرية** بحسب تصميم Firebase، فهي تعرّف المشروع فقط، والحماية كلها في القواعد.
**لا تضعي في أي ملف:** كلمة مرور، أو ملف «Service account»، أو «Private key».

## 3. أول تشغيل بعد الربط

1. افتحي الموقع وسجّلي الدخول بحسابكِ.
2. تظهر شاشة **تهيئة النظام**: اكتبي العام الدراسي ← «تهيئة النظام». ستُنشأ الفصول التسعة.
3. **إدارة الطالبات ← استيراد كشف فصل**: ارفعي «كشف أسماء الطالبات بالفصل» من نور (PDF) لكل فصل. يُكتشف الفصل من رأس الكشف، وتظهر الأسماء للمراجعة والتعديل قبل الحفظ. يُقرأ الاسم فقط، ولا يُقرأ رقم السجل المدني. البدائل: لصق الأسماء يدويًا، أو ملف CSV (الاسم، الصف، الفصل).
4. **الأسابيع والمفاتيح**: أنشئي الأسبوع الأول مع مفتاح الإجابة ← «فتح للرصد» ← «تعيينه حاليًا».
5. **المعلمات**: أنشئي حساب كل معلمة من Firebase Console ← Authentication ← Add user. عند دخولها أول مرة يظهر لها «رمز الحساب»، فترسله إليكِ وتضيفينه من شاشة **المستخدمات**.
6. بعد كل جولة رصد: **الأسابيع والمفاتيح ← نشر النتائج الحالية**، فتتحدّث شاشة العرض خلال 5 دقائق.

## 4. النشر على GitHub Pages

> سأطلب منكِ اسم المستخدم واسم المستودع عند هذه الخطوة. في الخطوات أدناه `<اسم-المستخدم>` و`<اسم-المستودع>` مكانان تملئينهما أنتِ.

1. في Safari افتحي **github.com** وسجّلي الدخول.
2. **+** ← **New repository** ← اكتبي `<اسم-المستودع>` ← اختاري **Public** (الخطة المجانية تشترطه لـ Pages) ← **Create repository**.
3. فكّي ضغط ملف المشروع في تطبيق «الملفات».
4. في صفحة المستودع: **Add file ← Upload files** ← اختاري محتوى المجلد (لا المجلد نفسه)، بحيث يكون `index.html` في الجذر ← **Commit changes**.
5. **Settings ← Pages** ← Source: **Deploy from a branch** ← Branch: `main` و `/ (root)` ← **Save**.
6. بعد دقيقة إلى دقيقتين يصبح الرابط: `https://<اسم-المستخدم>.github.io/<اسم-المستودع>/`
7. **مهم:** Firebase Console ← Authentication ← **Settings ← Authorized domains ← Add domain** ← `<اسم-المستخدم>.github.io`.

لتعديل `js/firebase-config.js` لاحقًا من الآيباد: افتحي الملف في GitHub ← رمز القلم ← الصقي ← **Commit changes**.

**إضافة النظام إلى الشاشة الرئيسية:** Safari ← زر المشاركة ← «إضافة إلى الشاشة الرئيسية».

## 5. الاختبارات: ما شُغّل فعلًا وما لم يُشغَّل

| الاختبار | الحالة |
| --- | --- |
| `tests/scoring.test.mjs`: قاعدة الاحتساب واستيراد CSV (11 حالة) | **شُغّل ونجح** (`node --test tests/scoring.test.mjs`) |
| `tests/ui-demo.mjs`: الواجهة في متصفح Chromium بالوضع التجريبي، ومنها استيراد كشف نور حقيقي (47 فحصًا) | **شُغّل ونجح** |
| `tests/rules.test.mjs`: قواعد الأمان على محاكي Firestore (17 حالة) | **لم يُشغَّل**: بيئة التطوير لم تسمح بتنزيل أدوات Firebase |

اختبارات الواجهة تتحقق من الواجهة والاحتساب في الوضع التجريبي، **لا** من قواعد الخادم.
قبل الاعتماد على الحماية يجب تشغيل `tests/rules.test.mjs` على المحاكي، أو تجربة الحالات يدويًا بعد الربط.

## 6. ملخص الأمان

- لا قراءة ولا كتابة عامة إلا قراءة `public/board` (أسماء مختصرة وفصول ونقاط فقط، بلا أرقام طلابية).
- الصلاحية تُقرأ على الخادم من `users/{uid}`. إخفاء الأزرار في الواجهة للراحة فقط، وليس هو الحماية.
- كل رصد يتحقق منه الخادم: النقاط = 5 لكل صحيحة + 5 عند صحة الثلاث، والمجاميع تزيد بالفرق نفسه بالضبط، ومعه قيد في سجل التدقيق.
- المعلمة لا تغيّر مفتاح الإجابة ولا حالة الأسبوع، ولا تعدّل إلا ما رصدته والأسبوع مفتوح.
- سجل التدقيق يقبل الإضافة فقط.
- لا حذف للمشاركات أو الطالبات من الواجهة. الإيقاف بديل الحذف ويحفظ التاريخ.
